# 中文附属包与本地化边界

> 核对日期：2026-08。案例：MoonLight 中文附属（v14，79 键）。

## 1. 中文附属包做法

1. **从 en_us.json 出发**：逐键翻译，**只翻值不翻键名**。
2. **覆盖策略**（v14 实测）：按域分组——
   - 6 材料 × 剑/斧/镐/锹/锄
   - 弓/弩/盾牌（16 色）
   - 锁链/铁/金/钻石/下界合金全套防具 + 马铠
   - 特殊物品（玩家头颅/火药/纸/燧石/木炭/橡木门）
   - 共 79 键起步（v14 交付量）。
3. **键完整性**：跑 `mc_pack_validate` 对照 en_us 补全缺失键。
4. **字形**：生僻字缺字形 → 位图字体补（1.19.3+，见 minecraft-pack-textures）。

## 2. 服务端字面名边界（关键结论，v14 九.3）

- `custom_name` / `item_name` 组件是**服务端写死的字面文本**，不走语言文件键——资源包**无法翻译它们**。
- 服务端物品（MMOItems 的 `MMOITEMS_NAME`、MMOCore 奖励等）显示中文 = **改服务端配置**：
  1. 服务端配置文件找到对应物品的 name（如 MMOItems 的 `BLUE_DIAMOND4` → `MMOITEMS_NAME: "&1Blue Diamond Boots"`）
  2. 改成中文（如 `"&1蓝钻靴子"`），注意颜色代码 `&` 前缀保留
  3. `reload mmoitems`（或重启）
- **拼写错误**同理是服务端问题：客户端条件永远匹配不上服务端写错的字面名（v14 "Blue Biamond" 案）——修服务端，或条件双通道兼容（`*Blue*iamond*`，见 minecraft-pack-cit）。

## 3. 语言选择无关性

- 26.2 客户端语言选简体中文时，UI/物品键名走 zh_cn 语言包（附属包补）；**服务端字面名（item_name/custom_name）不随语言变**——它是字面文本。（26.x 后续版本同理；具体某版是否随包带 zh_cn 需查该版 jar。）
- 结论：想让服务端物品在**任何语言**下都显示中文 → 服务端改名是唯一路径；想按语言显示 → 服务端按玩家语言下发（服务端逻辑，超出资源包范畴）。

## 4. 常见坑

- 把服务端物品名当语言键写进包（无效）。
- 用 `item.*` 键覆盖服务端物品（服务端字面名优先显示，覆盖无效）。
- zh_cn.json 带 BOM（部分编辑器默认）→ 加载异常（validate 检出）。
- 键值里未转义的引号/换行 → JSON 损坏。
